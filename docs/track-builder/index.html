Track Builder tutorial

Draw a Full Throttle Flux track by hand in the Godot editor, key its banks and widths, drop in loops, rolls, jumps and forks, then build, validate and dress it.

What it is

The Track Builder is a node you add to a track scene. You draw the shape of the lap as an ordinary Path3D curve and drop small key and feature nodes along it. The builder turns all of that into the road, walls, junctions, respawns, start grid and AI route laps the game runs on.

Everything here happens in the Godot editor, with feedback a fraction of a second after each change. Builder Lab (scenes/tracks/builder_lab.tscn) uses every part of it, and every picture on this page is taken from it.

The four circuits (Utopia, Swoopy, Hairpin Alley and The Drop) were built the old way and stay as they are. The builder is for new tracks.

The four rules

The old circuits carry a small rotation on their road geometry, which puts the road up to 21 m off its spline far from the origin. Every system that trusts the spline, from AI lines to respawns and cameras, was then wrong by that much. The builder makes that impossible by keeping four rules, and the validator checks every one.

  1. Never move or rotate a track node. To change the road, edit the curve or a key, never the node.
  2. The road surface is the spline. The driving surface sits exactly on the centre line.
  3. Banking comes from bank keys only. Don't type curve tilts. The builder solves them for you.
  4. One source of truth. Road, walls, zones, jumps, junctions, respawns, the start and the AI's route laps all come from the same curve and keys, in one Build.

The editor

  1. Scene tree: the TrackBuilder, its BaseSpline, and folders of keys and features.
  2. 3D view: the preview ribbon, coloured by the current overlay, with labelled gates for each feature and zone.
  3. Inspector: the TrackBuilder's settings and its Build and Validate buttons.

The layout under the TrackBuilder is up to you. Builder Lab keeps each kind of key in its own folder (BankKeys, WidthKeys, Features, GreebleZoneKeys and so on), which keeps a long lap manageable. The builder finds keys wherever they are under it.

Everything Build generates (MainSpline, the junctions, the start) sits beside the TrackBuilder, not under it, and is tagged so Build can update it in place.

Your first track

  1. Make the scene. A Node3D root with a TrackBuilder child. Under the TrackBuilder, a Path3D named BaseSpline with a closed curve. Add a WorldEnvironment and a sun as ordinary nodes, plus a fill light from below if you'll have loops or rolls.
  2. Draw the base by dragging BaseSpline's points and handles. Leave the straights straight where features will go.
  3. Key the banks and widths with BankKey and WidthKey nodes dropped near the track.
  4. Place the start with a StartKey on a straight.
  5. Add features: RollFeature, LoopFeature, JumpFeature, BranchFeature, and BoostPadKeys.
  6. Build, then Validate, and fix what it finds.
  7. Dress it with greeble zones, road surface zones and decals.
  8. Add it to the game, drive it, and train the AI.
Building unchanged inputs leaves the scene file byte for byte the same, so you can Build as often as you like and Git only shows real changes.

The base curve

BaseSpline is the shape of the lap as you drew it. The ribbon follows it within a fraction of a second while you drag a point. Draw the shape, not the details: banks, widths and features all come from keys.

SettingWhat it does
fairing_m (40)Smooths the step in curvature at each control point over this many metres, so hand-set handles don't jolt the ship. It moves the curve by centimetres. 0 = exactly as drawn.
start_lead (30)The generated lap starts this far before the start line.
overlayWhat the ribbon's colour shows (below).
ribbonThe coloured ribbon on or off. Build turns it off so you can see the real road.
ref_speed (110)The speed the cornering overlay and checks assume.
label_every (100)Distance labels along the track; 0 hides them.

Keys stay put in the world when you edit the curve upstream of them, and each key's marker snaps to the nearest point of the track.

On Builder Lab fairing moves the curve by at most 3 cm and you can't see it in the ribbon, because its handles are already smooth. It matters when you drag a handle sharply: the validator's kink check catches what fairing doesn't smooth out.

Overlays

The ribbon's colour is your fast feedback. Pick an overlay on the TrackBuilder and check the whole lap at a glance before you ever Build.

Purple gates mark each feature's footprint, cyan posts mark where a fork's junctions end, orange outlines with a chevron are boost pads, green gates start greeble zones and blue ones start surface zones.

Bank keys

A BankKey sets the road's lean at one point. Between keys the bank eases from one to the next. Drop the node anywhere near the track; its marker snaps to the closest point and the label shows its angle.

SettingWhat it does
bank_degLean in degrees, + = right. ±80° at most.
easeHow the bank changes from this key to the next: smooth (the default), linear, hold (then step), or smoother.
distance (read only)Where it landed, in metres along the track, and how far the node is from it.
Never type a tilt into the curve's points. Godot's frame twists on its own through 3D curves, so the number you type isn't the bank you get. The builder solves the tilts to within 0.02°.

Example: a steeper bank

One key's bank raised by 18°. The ribbon's colour deepens on both sides of it, because the bank eases in and out over the distance to its neighbours.

Width keys

A WidthKey narrows or widens the road. Each half is set from the centre line, so the two sides can differ, for a run-off on the outside of a corner say.

SettingWhat it does
linkedOn: both halves move together.
half_width_left, _right6 to 45 m each. The standard road is 21.5 m each side.

Spread width keys out: the validator flags a change of more than 0.1 m per metre, where the wall would cut across the racing line. Under 10 m a side is tight for eight ships and respawns.

Example: a wider left side

One key's left half widened by 10 m, in the width overlay. Orange is wider than standard.

The start

A StartKey goes where the start line goes, on a straight. The grid forms up behind it, and the generated lap begins start_lead metres before it.

The validator wants the grid on the level and on a straight: under 1 g at 110 u/s and under 3% grade, with every grid slot over the road. Features can't start right after the line or run into the grid.

Barrel roll

Features replace a stretch of your curve, its footprint, with their own shape, fitted on like a path deformer. They start and end exactly on your curve, and nothing outside the footprint moves. Drop the feature node where you want its middle.

A RollFeature turns the road once about the direction of travel, and keeps the centre line yours. It comes with a magnetic zone that holds ships to the road.

SettingDefaultWhy
length800 mThe peak roll rate is 1.5 × 360 / length °/m. Under about 720 m it's over 0.75°/m, which is an error: 460 m threw ships into the wall.
direction, turnsright, 1
magnet_strength11 = forgiving, ships can crawl round upside down. 0 = needs speed.

Example: a roll that's too short

The roll cut from 800 m to 560 m, in the roll rate overlay. The middle of it turns red: about 0.96°/m, past the limit, and Validate reports an error.

Loop

A LoopFeature is Loop Lab's teardrop: 820 m of arc with a 65 m top radius, stepping sideways so the exit clears the entry. An S-jog before and after moves the road out and back, so the exit lands exactly on your curve.

SettingDefaultNotes
loop_length820 mTop radius ≈ length / 4π
shift, side90 m, rightHow far the exit steps beside the entry
jog_length300 mEach S-jog. The whole footprint is about 960 m
magnet_strength1As the roll

Put it on a straight, level stretch. The validator warns past 15° of turn or 3% grade under it. Inverted road needs light from below.

Jump

A JumpFeature is a climb, a run-up, a kicker, a real gap with no road under it, a landing ramp and an outrun. The climb makes the whole jump height-neutral, so the road after it is where you drew it. A respawn trigger sits under the gap.

SettingDefault
kicker_deg / kicker_length6° / 70 m
gap / drop55 m / 4 m
landing_deg / landing_length / outrun6° / 40 m / 80 m
runup64 m of level road before the kicker
respawn_runup250 m with no respawn points before the kicker

clean_speed is the slowest speed at the lip that still lands cleanly. Don't guess it: measure_jumps flies the real ship off the exact shape and stores the answer. Change the shape and the validator says the value is stale.

Split track

A BranchFeature is a second route that leaves the main track and rejoins it; racers and the AI choose. Under it, draw a Path3D named BranchBase, an open curve from a point on the main road to a later one. Its own bank keys, width keys, jumps and boost pads go under the BranchFeature too.

The builder snaps the branch's ends onto the main road over junction_blend (150 m), ends each junction where the two centre lines are 62 m apart, and levels both roads across each junction. Draw the branch well clear of the main road, and leave and rejoin on the same side.

Boost pads

A BoostPadKey puts the game's boost pad (8 m wide, 12 m long) on the road. It doesn't change the road, so it's a key, not a feature. Pads sit on the surface at the nearest point of the finished track, facing the direction of travel and banked with the road, loops and rolls included.

SettingWhat it does
anchor, offsetMeasured from the centre line, or in from the left or right edge. An edge-anchored pad stays against the edge where the width changes.
count, spacingUp to five pads side by side, 10 m apart by default.
strength150 u/s added on top of the ship's speed.

A +150 pad at full speed takes default_racer from about 116 to 266 u/s, back to normal by about 300 m. So leave about 250 m of road after a pad before anything tight; the validator follows that speed into the corners, crests and jumps ahead.

Build

Build on the TrackBuilder writes the track the game runs on: MainSpline with its road and wall segments, the branch spline, the junctions, respawn points, the start line and grid, and the AI's route lap through each branch. Change anything and Build again; it updates the generated nodes in place. Clear build removes everything it made.

The TrackBuilder removes itself when the game runs: it's authoring data only. What it generated is what the game uses.

Validate

Validate checks the four rules and the limits learned from the circuits, Loop Lab and Fork Lab. It draws problems on the track, red for errors and amber for warnings, and lists them in the TrackBuilder's Report group. Errors stop the track being right; warnings are things to look at.

What the messages mean

MessageWhat to do
X has a non-identity transformSomething moved a track node. Reset its transform and edit the curve instead.
Build is out of dateBuild.
Roll rate over 0.7°/mSpread the bank keys further apart, or lengthen the roll.
Width changes over 0.1 m per mSpread the width keys.
Key is more than 30 m from the trackMove it closer: it may attach to the wrong stretch.
Corner over 15 g at 110 u/sOpen the corner, or accept a hairpin.
Kink: curvature jumps over 1.0 g/mSmooth the handles, or raise fairing_m.
Crest needs over 110 u/s²The road falls away under a ship at racing speed. Soften the crest, or make it a jump.
Racing speed at the lip under clean_speedMove the jump after a straight, or make it smaller.
Branch never gets 62 m clearDraw the branch further from the main road.
The boost carries X u/s into the bendMove the pad further from the bend, or lower its strength.
Greebles …: reaches into the trackFix the rule's offset, lateral or scale, or skip that layer in the zone.

The full list, with the measurements behind every limit, is in TRACK_AUTHORING.md.

Greebles

Greebles are the track's dressing: lamps, wall panels, railings, light strips, pylons and gantries. A GreebleZoneKey starts a zone, and its style runs to the next key along the track. Build first: greebles sit on the built road, so they follow width keys, loops and rolls, and leave gaps and junctions bare by themselves.

SettingWhat it does
presetA style from the library: civic, garden, hairpin, maritime, service, skyway or sky_deck. None = a bare stretch.
mirrorSwaps left and right. Turn chevrons belong on the outside wall, so mirror a zone of right-handers.
density, seedMultiplies every rule's probability; reshuffles the random parts.
skip_layersLeaves out ground, wall face, wall top, outside or overhead pieces.

Editing a preset changes every zone that uses it, on every track. Make local copy gives one zone its own copy. The dressing updates about 0.2 s after you stop moving a key.

To tune the styles themselves, with the road surface beside them and before/after comparisons, use Surface Lab.

Road surface

The road is drawn by one procedural shader: plate, ribbed and grate lanes, channels with guide lights, painted edges and hazard stripes. What runs across the road is a profile, and a SurfaceZoneKey picks the profile for a stretch of track.

SettingWhat it does
presetindustrial, service or grate_run.
blend_inCross-fades from the zone before over this many metres. 0 = a hard seam.
seedReshuffles panel offsets, tints and vents.
wearHow worn this stretch looks, times the track's age.

A path can use at most four different profiles. The track's own deviations from the shared look go in a TrackSurfaceVariation on the TrackBuilder's surface_variation.

Profiles, colours, masks and wear are tuned live in Surface Lab, which shows each change on the road as you drag.

Road decals

A SurfaceDecalKey paints words, stencils, numbers, barcode serials, chevrons and arrows on the road. Text reads for a ship coming along the track.

SettingWhat it does
shapetext, chevron or arrow.
roleThe font by job: WORD (BBH Bartle), STENCIL (Alien Block), LABEL (Audiowide), SERIAL (Libre Barcode 39).
text# counts up with each copy: SECTOR #.
size, widthLetter height; for shapes, length and width.
paint, glow, opacityWhite, yellow, red or blue (no orange: that's the boost pads). Glow 1 is lit like the guide lights.
count, spacingCopies along the track.

Sizes that work: BBH Bartle is very wide, about 1.1 m of road per metre of letter height and character, so a long word wants 2 m letters on a 39 m road; chevrons 3 to 4 m long; serials about 1 m. Far away a decal fades to its paint's average, barcodes first. The validator warns about characters a font can't draw.

Into the game

  1. Save the scene as scenes/tracks/<id>.tscn. The game finds it by id.
  2. Make resources/tracks/<id>.tres, a TrackProfile with track_id = "<id>" and a display name. Copying builder_lab.tres is easiest.
  3. Add it to resources/tracks/track_manifest.tres.

Training the AI

On default_racer, from a fresh bake:

  1. Add the scene to TRACKS in tools/train_ai_lines.gd (and to ROUTES as [-1, 0, ...] if it has branches).
  2. Train: 
    godot --headless --path full_throttle_flux res://tools/train_ai_lines.tscn -- --track=<id> --fresh
  3. Race it, and look for no respawns, wall contacts, the shortcut's take rate and pad hits: 
    PROBE_TRACK=<id> PROBE_SECONDS=240 PROBE_SEED=1234 godot --headless --fixed-fps 60 --path full_throttle_flux -s res://tools/dev/ai_race_probe_boot.gd
Retrain whenever you rebuild after changing the geometry: the trained line is tied to the road it was driven on. The road's wear follows the trained line too.

Command line

The editor buttons do the same as these, which are handy for checking a track headless:

# build and validate
godot --headless --path full_throttle_flux -s res://tools/track_builder/build_boot.gd -- --scene=res://scenes/tracks/<id>.tscn
godot --headless --path full_throttle_flux -s res://tools/track_builder/validate_boot.gd -- --scene=res://scenes/tracks/<id>.tscn
# fly the real ship off each jump and store clean_speed
godot --headless --fixed-fps 60 --path full_throttle_flux -s res://tools/track_builder/measure_jumps_boot.gd -- --scene=res://scenes/tracks/<id>.tscn
# greeble counts, pieces left out, intrusions
godot --headless --path full_throttle_flux -s res://tools/track_builder/greeble_stats_boot.gd -- --scene=res://scenes/tracks/<id>.tscn

Limits

  • New tracks only. The four circuits keep their old geometry and their offset; the runtime copes by ray-casting the road.
  • Features can't overlap each other, run across the start line, or sit in a fork's junction.
  • Four surface profiles per path, and keep blends to a few tens of metres.
  • Bank keys inside a loop or jump do nothing; the feature fades the bank out and back in. Inside a roll they add to it.
